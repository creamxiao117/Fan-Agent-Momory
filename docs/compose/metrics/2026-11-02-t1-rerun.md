> 数据源：`python -m scripts.rule_following_timeseries`（`retro/snapshot-*.json` + `retro/lint-report-*.md` + ingest 账本）
> 基线：`docs/compose/metrics/2026-09-23-t1-baseline.md`（首轮结论「未成立」）
> **口径变更（同步记录）**：脚本里的「后窗口」原硬编码为**改造后 2 天**（`2026-09-23`~`2026-09-24`）——

## 结论（诚实口径）

1. **门禁侧已收敛**：改造日（2026-09-23）之后的 **37 个有数据天**，lint 五个维度（invalid / schema_drift / orphans / ghosts / stale）**全 0**，无一次复现。
2. **但整体命题「规则遵循/返工改造见效」不成立**：知识**流入侧**没有恢复 —— 近期 ingest 几乎只产出「重复」而非「新知识」（W40–W45：入区 2 张 / 重复 60 条）。
3. ⇒ **根因不在门禁漂移，而在「同一知识被反复提交」**：
   - 冲突判决分解（182 条）：真重复 **34** / 误杀 **8** / 不确定 **126** / 无注记 **14** ⇒ 绝大多数（69%）判为**不确定**，去重链没有拦住重复。
   - 被反复提交的卡（≥2 次，共 12 张）：`llm-dedup-gateway-degrade-fix.md` **4×**、`flywheel-weixin-rate-limit-diagnosis.md` **4×**、`skillhub-chain-junction-e2e-verification.md` 2×、`pandoc-document-conversion-blueprint.md` 2×、`mcp-server-mcp-version-mismatch.md` 2× ……
4. **下一步诊断方向（不在本轮范围）**：查「反复提交」的上游来源（多平台并行蒸馏 / cron 无人值守重跑 / 人工重复沉淀），而不是继续加固门禁。

## 可比性缺口（继承首轮，仍然存在）

- lint 报告有两种格式：**A**（报 孤儿/无效/幽灵）与 **B**（09-08 起，报「发现问题数」并新增 `long_desc`/`short_desc` 维度）⇒ **跨格式不能比大小**；只有 `invalid` 在两格式与快照中同义可比。
- 快照序列缺 2026-10-04 ~ 10-23 的部分天（68 份覆盖 08-17 ~ 11-02，但**并非每天都有**）⇒ 后窗口按「有数据天」计，不按日历天计。
