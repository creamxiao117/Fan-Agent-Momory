## A. 结构性缺陷（最高价值）

### A1. `authority_dirs` 有 6 份副本 / 4 种内容，且"声明源"无人消费

`common/config.py::HubConfig` 只暴露 `platforms` / `draft_dir` ⇒ **`hub.config.yaml` 的
`authority_dirs` 没有任何消费方**，各模块各自硬编码：

| 位置 | 内容 | 问题 |
|---|---|---|
| `hub.config.yaml` | 5 权威区 + `experience` | **基准，但无人读** |
| `tools/lint.py::AUTHORITY_DIRS` | 5 权威区（**缺 experience**） | 与 09-10 "experience 升级进权威区"矛盾 |
| `scripts/index_consistency.py::AUTHORITY_DIRS` | 同上（缺 experience） | 注释自称"与 hub.config.yaml 对齐"，**实际不对齐** |
| `tools/mcp_policy.py` / `scripts/metrics_daily.py` | + **libs** + **retro** | `libs` 未在 config 声明；`retro` 被 config 明确列为**非**权威 |
| `scripts/secret_sentry.py` | + **notes** | `notes` 被 config 列为**非**权威 ⇒ 误报高危 |
| `tools/retrieve.py::_ACTIVE_DIRS` / `tools/hub_registry.py::CARD_DIRS` / `common/gate_scope.py::L0_PREFIXES` | 5 权威 + experience | ✅ 正确 |

**可观测后果**（实跑）：
- `engine.py lint` → `共检查 284 张卡片`；而 experience 实有 **236 张** ⇒ 该区**不参与孤儿/陈旧判定**。
  实测把 experience 并入后 `孤儿 0 / 幽灵 0`（新增 0）⇒ **当前无故障，是潜在盲区**（下次真出问题必漏）。
- `engine.py status` 卡片分布只有 `blueprints/longterm/methodology/projects/rules`，**永久漏 experience**。
- `engine.py audit` 输出「INDEX 条目 **520** / 权威区文件 **284**」自相矛盾（520 = 284 + 236）。

**修复（建议）**：新建 `hub-engine/common/authority.py` 持有唯一字面量
（`AUTHORITY_DIRS` / `NON_AUTHORITY_DIRS` / `CARD_DIRS` / `DIR2TYPE`），6 处改为 import；
新增一条测试断言 `hub.config.yaml.authority_dirs == AUTHORITY_DIRS`（口径同
`test_index_consistency::test_authority_dirs_is_audit_source_not_copy`，但覆盖全部副本）。

## C. 门禁假绿（上一轮已报，仍存在）

`gate_runner.gate_text` 用 `subprocess` 直接执行 `markdownlint`（npm 的 `.cmd` 垫片），
Windows `CreateProcess` 不解析 `.cmd` ⇒ 恒返回 127 → 「未安装，跳过」**静默失效**。
存量违规实测：`rules/global-rules.md` MD012×2、`methodology/post-task-recommendations.md` MD025、
`experience/pluginhub-agents-md-hub-quote.md` MD047。
**未擅自启用**：一启用会拿存量基线大规模阻断他人提交（属政策决策）。
